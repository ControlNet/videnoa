## Remaining release steps

1. Let the exact-source CI complete, including packaging and Docker gates.
2. Follow the established GitFlow release process: create `release/0.1.4` from dev, bump the workspace version and the five workspace lockfile package entries, verify locked metadata, and require the release candidate's full CI to pass.
3. Recheck a representative NAS-to-GPU iroh upload/processing/download and restart identity on the target networks. Earlier automated Windows/loopback tests do not prove real NAT/forced-relay performance, and the reported relay Ping timeout has not been conclusively diagnosed. This is an acceptance evidence gap, not a proven release regression.
4. Merge the tested release branch into master to trigger the existing Release Workflow. Do not pre-create the tag: the workflow owns tagging and publication after gates. Verify both platforms' archives, both Docker image version/latest tags, then synchronize master back to dev.
